# CLAUDE.md

Правила работы с этим репозиторием.

## Источник истины

- **Поведение определяет код и зелёный прогон.** Если документ расходится с
  кодом — прав код, документ идёт на правку.
- Замысел — `docs/2026-10-17-cabinet-design.md`, владелец темы там. В других
  местах на него **ссылаются**, а не пересказывают.
- Задания — `docs/plans/2026-10-17-cabinet-implementation.md`.

## Как работаем

- **Разработка от тестов.** Тест пишется раньше кода. Задание не закрыто, пока
  тест не написан и не проходит.
- **Работаем на mock-данных.** Живая база и живая почта подключаются на
  последней волне (W6). До этого — только фикстуры. Так же устроен Android-клиент
  в `vpn-app-design`: там `MockApi` имитирует все эндпоинты и живёт в тестах.
- **Каждое задание сперва заводится в трекере**, потом берётся в работу.
  Взятое задание помечается как начатое.

## Границы сервиса

- Кабинет **не трогает MySQL**. Только внутренний HTTP к боту на `127.0.0.1`
  с общим секретом. Этот репозиторий публичный — SQL и схемы таблиц
  авторизации в него не попадают.
- Внутренний роутер бота наружу не выставлен.

## Безопасность связывания

Тема самая опасная в проекте, её правила обязательны:

- `chat_id` присваивается **только** после подтверждения в Telegram. Никогда —
  по заявленному в браузере.
- `mail` не существует без `mail_verified_at`.
- Привязка — только на `NULL`, через `WHERE id = ? AND chat_id IS NULL`.
  Занятое значение **никогда** не перезаписывается.
- **Отвязка последнего способа входа запрещена.**

Класс ошибки, которого здесь избегаем: CVE-2026-53516 (Better Auth), nOAuth
(Microsoft). Оба — авто-связывание по заявлению провайдера без проверки
локальной записи. Разбор — §3.3 спеки. Любая правка в связывании должна
оставлять зелёным тест W3.4, воспроизводящий эту атаку.

## Публичность

Репозиторий публичный. В код, доки, issue и комментарии **не попадает**:

- IP-адреса серверов, имена хостов, домены раздачи;
- ключи, токены, секреты, содержимое `.ovpn`, PEM-блоки;
- адреса и данные клиентов.

Формулировка от обратного: **если деталь нельзя положить в коммит публичного
репозитория — её нельзя и в issue.**

## Трекер

Находки и задачи — в GitHub Issues этого репозитория. Метки по трём осям:
тип (`bug`/`feature`/`idea`/`task`), область (`web`/`backend`/`docs`/`infra`),
приоритет (`P0`/`P1`/`P2`). Статус в метках не дублируется.

Правило: issue — **только сырьё**. Проработанная тема уезжает в `docs/`, issue
закрывается ссылкой и содержания спеки не дублирует.
