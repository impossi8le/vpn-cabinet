# vpn-cabinet

Веб-кабинет VPN-сервиса. Вход **по почте или по Telegram — на выбор**, с
возможностью связать оба способа в один аккаунт.

## Зачем отдельный вход по почте

Аккаунт в сервисе сегодня существует только в Telegram: «аккаунт» — это
`chat_id`. У человека без доступа к Telegram доступа к своему аккаунту нет
вообще. Для VPN это замкнутый круг: **чтобы получить VPN, нужен VPN** — в части
сетей Telegram недоступен.

Поэтому вход и регистрация — **на выбор: почта или Telegram**. Почта
рекомендуется, потому что выручает, когда Telegram недоступен, но ни один из
двух способов не обязателен. Связать их можно в любую сторону: привязать
Telegram к аккаунту, заведённому по почте, или привязать почту к аккаунту из
Telegram.

## Состояние

**Работает на боевом сервисе:** https://utilio.cc. Приложение — systemd-юнит
`cabinet-app`, внутренний API аккаунтов — `cabinet-api`; с ботом кабинет
общается по внутреннему HTTP `127.0.0.1:8007` с общим секретом.

```bash
python -m cabinet        # приложение на 127.0.0.1:8000
```

Что уже есть: вход по почте и по Telegram, привязка обоих способов, подписки,
покупка (`/buy` → серверы → оплата ЮKassa → `/buy/done`), смена региона,
скачивание конфига, отвязка с подтверждением.

667 тестов, прогон зелёный (2026-11-11).

## Границы с другими репозиториями

Кабинет **не ходит в базу напрямую**. Он обращается к боту по внутреннему HTTP
на `127.0.0.1` с общим секретом. Причина — этот репозиторий публичный: в нём
не должно быть SQL-запросов и схемы таблиц авторизации.

| Репозиторий | Что там | Видимость |
|---|---|---|
| `impossi8le/vpn-cabinet` | этот кабинет | публичный |
| `impossi8le/vpn-app-design` | Android- и iOS-клиенты, контракт API | публичный |
| Репозиторий бота | бот, работа с базой, внутренний API | приватный |
