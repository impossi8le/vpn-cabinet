# План: боевые зависимости кабинета (issues #45, #46)

Дата: 2026-10-23. Задания — [#45](https://github.com/impossi8le/vpn-cabinet/issues/45)
и [#46](https://github.com/impossi8le/vpn-cabinet/issues/46).
Причина: выкладка на сервер. Юнит `cabinet-app.service` (в репозитории бота)
запускает кабинет командой `python -m cabinet`, а она собирала приложение
**на подставном боте** (#45), и даже после этого первые два экрана отдали бы 500,
потому что живой клиент не подходит на роль хранилища (#46).

## Что чиним

`cabinet/__main__.py` вызывает `build_app()` без аргументов, и умолчания берут
подставные зависимости: `_default_store()` → `tests.fakes.FakeApi`,
`_default_mail_sender()` → отправитель с `FakeMailSender`. Выложенный так кабинет
войдёт любым адресом и покажет подписки из фикстур.

## Общие ограничения

- Кабинет **не ходит в базу** — только внутренний HTTP к боту на `127.0.0.1` с
  общим секретом (CLAUDE.md, «Границы сервиса»).
- **Секреты не печатать**: ни в код, ни в тесты, ни в коммиты, ни в вывод.
- Репозиторий публичный: ни IP, ни хостов, ни домены в код и тесты не попадают.
- Тесты — на подставных данных; живой бот подключается только в бою.
- Непустые тесты: снять защиту — тест обязан покраснеть.

### Task 1: точка входа собирает приложение боевыми зависимостями

**Файлы:** `cabinet/__main__.py`, `.env.example`, `tests/test_entrypoint.py` (новый).

**Требования:**

1. `python -m cabinet` собирает приложение боевыми зависимостями:
   - хранилище — `cabinet.bot_client.BotClient` по `BOT_BASE_URL` и общему секрету
     (адрес роутера бота, `http://127.0.0.1:8007` в бою);
   - отправитель писем — из окружения (`MailSender.from_env`, как уже умеет
     модуль).
2. **Без обязательных переменных окружения — не подниматься.** Отсутствие
   `BOT_BASE_URL` или секрета даёт понятный отказ и ненулевой код выхода.
   Молчаливый откат на подставного бота и есть дефект: неверная конфигурация не
   должна выглядеть рабочей.
3. **Имя переменной секрета — `CABINET_INTERNAL_SECRET`**: так его называет юнит
   выкладки в репозитории бота. В `.env.example` сегодня `BOT_INTERNAL_SECRET` —
   привести к одному имени, чтобы два имени не разошлись при развёртывании.
4. Порядок запуска не меняется: порт берётся из `CABINET_PORT`, слушаем
   `127.0.0.1`.

**Шаги:**

1. RED: тест «без переменных окружения запуск отвергается» и тест «с переменными
   собирается `BotClient` с теми же значениями».
2. Реализация: сборка зависимостей из окружения, отказ при отсутствии
   обязательных.
3. GREEN: `pytest tests/test_entrypoint.py` и весь набор; `ruff check .`,
   `ruff format --check .`.
4. Коммит: `Точка входа кабинета: боевые зависимости из окружения (#45)`.

**Готово, когда:** без окружения запуск отвергается внятным текстом; с окружением
собирается `BotClient`; весь набор зелёный; `tests/fakes.py` не тронут.

### Task 2: живой клиент как хранилище (issue #46)

**Файлы:** `cabinet/bot_client.py` (или адаптер рядом с ним), `cabinet/app.py`
(докстрока и место сборки), `tests/test_store_adapter.py` (новый).

**Зачем.** Роуты кабинета зовут хранилище **синхронно**: `subscriptions_for`,
`find_by_id`, `get_balance`, `get_referral`, `unlink_preview`. У живого
`BotClient` таких методов нет, а его собственные — корутины. Значит выложенный
кабинет на первых же двух экранах отвечает 500. Тесты это пропускали, потому что
идут против `FakeApi`, у которого нужная форма есть по определению.

**Требования:**

1. Живой бот приводится к форме, которую ждут роуты. Точный список методов —
   **из кода роутов**, а не по догадке: пройти по `cabinet/app.py` и выписать,
   что именно зовётся у хранилища.
2. Асинхронность снимается **в одном месте** — как `_StoreConfigSource` для
   конфигов, а не по месту в каждом роуте. Выбор способа обосновать в
   комментарии: синхронный `httpx.Client` в адаптере или `asyncio.run` поверх
   корутин.
3. Адаптер отдаёт **сырые записи бота**, а не готовые представления: сборка
   `SubscriptionView` остаётся там, где она есть (`subscriptions.subscription_views`).
4. Тест проверяет **реальный роут**: `GET /subscriptions` с сессией против
   подставного HTTP (как `tests/test_client_against_fake.py`) — бот вернул список,
   и экран его показал. Тест против одного клиента или против `FakeApi` этот
   дефект пропускает, поэтому он не годится.
5. Докстрока `AccountStore` в `cabinet/app.py` перестаёт обещать то, чего нет:
   сейчас она утверждает, что живой клиент даёт эту форму «уже сейчас».

**Шаги:**

1. RED: тест на реальный роут против подставного HTTP — падает (500 или
   отсутствие метода).
2. Реализация адаптера и его подключение в `build_from_env`.
3. GREEN: новый тест, весь набор, `ruff check .`, `ruff format --check .`.
4. Коммит: `Живой клиент как хранилище: роуты больше не падают (#46)`.

**Готово, когда:** `GET /subscriptions` и `GET /account` работают против живого
клиента (это доказывает тест), устаревшее обещание в докстроке убрано, весь набор
зелёный.

### Task 3: вход и привязка на живом клиенте (issue #47)

**Файлы:** `cabinet/bot_client.py` (дополнить `BotStore`), `tests/test_store_adapter.py`.

**Зачем.** `cabinet/signin.py` и `cabinet/linking.py` зовут семь методов, которых у
`BotStore` нет, — то есть на живом кабинете **вход по почте не работает вовсе**, а
это главная дверь: человек за границей может не иметь работающего Telegram до
того, как заработает VPN.

| Метод | Кто зовёт | Эндпоинт роутера |
|---|---|---|
| `find_by_mail` | вход и регистрация по почте | `GET /internal/accounts/by-mail` |
| `create_account` | регистрация по почте | `POST /internal/accounts` |
| `find_by_chat_id` | вход по Telegram, привязка | `GET /internal/accounts/by-chat-id` |
| `link_chat_id` | привязка Telegram | `POST …/link-telegram` |
| `link_mail` | привязка почты | `POST …/link-mail` |
| `unlink_chat_id` | отвязка Telegram | `POST …/unlink-telegram` |
| `unlink_mail` | отвязка почты | `POST …/unlink-mail` |

**Семантика, которую нельзя потерять:** привязка отвечает **числом** (`1` —
привязали, `0` — место занято); `chat_id_taken`, `mail_taken` и особенно
`last_login_method` обязаны дойти до своих отказов (`UnlinkRefused` — про
недоступный навсегда аккаунт, а не общий отказ). Разбор ошибок — общий с уже
написанным, второй копии не заводить.

**Тест:** реальный роут входа по почте против подставного HTTP — адрес не найден →
аккаунт заводится; найден → тот же аккаунт, второго не создаётся. Плюс отказ
привязки по занятому месту.

### Task 4: скачивание конфига на живом клиенте (issue #48)

`get_ovpn` в `BotStore` по образцу асинхронного метода (тот же путь, байтами),
отказы бота — в свои типы `ConfigError`, тест гоняет реальный роут скачивания.
Ревью: спека ✅, одобрено. Отдельно сверено с кодом бота, что идентификатор
подписки и идентификатор конфига — одно значение (`_config_id` в роутере), иначе
каждая отдача отвечала бы «конфиг не найден».

### Task 5: недоступность бота — честный отказ, а не 500 (issue #49)

`find_by_id` защищён, как соседние вызовы; тем же обработаны роут скачивания
конфига, экран способов входа, подтверждение привязки почты, отвязка и вход.
Различие «аккаунт исчез» (`404` → гасим сессию) и «бот недоступен» (сессия
жива) сохранено и проверено тестом на контрасте.

## Состояние на 2026-10-23: кабинет выложен

**Живой адрес:** `https://194-87-252-181.sslip.io:4444/` — имя того же вида, что у
клиентского API (`:4443`), сертификат уже лежал на сервере. Домена и DNS покупать
не потребовалось.

| Что | Где |
|---|---|
| Код кабинета | `/var/www/vpnbotfree_r_usr/data/www/vpn-cabinet` (клон публичного репозитория) |
| Окружение | `venv` с Python 3.12.15 (deadsnakes) — кабинет объявляет ≥3.11, системный 3.10 уже EOL |
| Настройки | `.env` рядом с кодом: `CABINET_PORT=8008`, `BOT_BASE_URL=http://127.0.0.1:8007`, `CABINET_INTERNAL_SECRET` (тот же, что у роутера) и почта |
| Почтa | SMTP-релей, которым уже пользуется бот (новый ключ не нужен; смена на Brevo — три строки) |
| Служба | `cabinet-app` (systemd), 127.0.0.1:8008, только loopback |
| Фронт | nginx, `deploy/zz-cabinet.conf` из репозитория бота, порт 4444, TLS, `X-Forwarded-Proto` |
| Роутер | `cabinet-api`, 127.0.0.1:8007, наружу не выставлен |

**Обновление после правки:** `git pull` в каталоге кабинета → `systemctl restart
cabinet-app`. Зависимости меняются — `venv/bin/pip install -e .`.
**Откат:** `systemctl disable --now cabinet-app` и `rm /etc/nginx/conf.d/zz-cabinet.conf`
(роутер и бот при этом не трогаются).

**Урок, который стоил бы дорого:** «служба отвечает 200» не значит, что она
собрана боевыми зависимостями. Первая выкладка поднялась из клона, сделанного до
правок, и работала демонстрацией: подставной бот, письма в никуда. Проверять надо
ревизию кода **на сервере**, а не только код ответа — и защита «не стартовать без
конфигурации» проверяется запуском, а не чтением теста.

## Review Focus

- **Отказ вместо подстановки:** ни один путь не должен оставить подставной бот в
  боевом запуске.
- **Секрет не печатается** нигде, включая текст отказа.
- **Публичность:** в тестах и коде — только зарезервированные адреса
  (`example.com`, `127.0.0.1`).
- **Стенд не сломан:** `.claude/dev/cabinet_dev.py` собирает приложение сам и
  правки не замечает — проверить, что он по-прежнему поднимается.
