# План: вход через Telegram в кабинете (issue #50)

Дата: 2026-10-24. Задание — [#50](https://github.com/impossi8le/vpn-cabinet/issues/50).
Причина: первая живая проверка. Вход по почте работает целиком, но показывает
пустой кабинет: подписки живут на `chat_id`, то есть на Telegram-аккаунте, а вход
по почте заводит аккаунт с `chat_id = NULL`. Пока не подключён вход через
Telegram, человек с подпиской видит «подписок нет» и решает, что потерял её.

## Что уже есть и чего нет

- **Есть:** флоу бота в публичном клиентском API — `POST /api/v1/auth/link`
  (тело `public_code`, `secret_hash`; ответ содержит
  `deep_link = https://t.me/<бот>?start=login_<код>`) и `POST /api/v1/auth/poll`
  (тело `public_code`, `secret`; ответы: `{"status":"pending","retry_after_ms":…}`,
  `{"status":"denied"}`, ошибки `invalid_secret` / `operation_not_found` /
  `already_consumed` / `nonce_mismatch`, а на успехе — `session_token` и
  **`account_id`**). Контракт — `docs/2026-10-17-backend-contract.md` §5.
- **Есть:** `SignInService.sign_in_with_telegram(chat_id, *, account_id=None)` —
  если бот отдал `account_id`, кабинет просто выдаёт сессию по нему.
- **Есть:** экран `render_login_telegram` и шаблон `login_telegram.html`.
- **Нет:** кабинет не начинает челлендж и не опрашивает бота — экран
  `/login/telegram` отвечает «ссылка ещё не готова».

## Общие ограничения

- Кабинет **не ходит в базу** — только HTTP к боту (CLAUDE.md).
- **Секреты не печатать**: `secret` челленджа живёт только в памяти процесса
  кабинета и в теле запроса к боту; в разметку, логи и коммиты он не попадает.
  В ссылку для человека уходит **только** `public_code` (её строит бот).
- Репозиторий публичный: адреса бота — параметр развёртывания, в коде и тестах
  только зарезервированные значения.
- Тесты — на подставном HTTP-боте; живой бот только в бою.
- Непустые тесты: снять защиту — тест обязан покраснеть.

### Task 1: кабинет начинает и завершает вход через Telegram

**Файлы:** `cabinet/bot_client.py` (клиент флоу), `cabinet/app.py` (роуты),
`cabinet/__main__.py` (если нужен новый адрес бота), `tests/test_login_telegram_live.py`.

**Требования:**

1. **Клиент флоу** — отдельный от внутреннего роутера: это публичный API бота, а не
   `/internal/*`. Отсюда два адреса: внутренний (аккаунты, подписки) и публичный
   (вход). Публичный берётся из окружения (`BOT_PUBLIC_BASE`), в бою — локальный
   `http://127.0.0.1:8006` (клиентский API слушает там) либо публичный адрес.
2. **Начало входа**: кабинет генерирует `public_code` и `secret` (`secrets`),
   отправляет боту `secret_hash`, получает `deep_link` и показывает его человеку —
   кнопкой «Открыть Telegram». Ничего не подделывать: `chat_id` приходит только из
   подтверждения ботом (§3.3).
3. **Завершение**: экран опрашивает `/auth/poll`. На успехе приходит `account_id` —
   кабинет выдаёт сессию **по нему** (`sign_in_with_telegram(..., account_id=…)`) и
   уводит на подписки. `pending` — ждать (взять `retry_after_ms` у бота), `denied` —
   «вход отклонён в Telegram», ошибки — своими текстами, не одним «не удалось».
4. **Состояние челленджа** живёт в памяти процесса кабинета (как коды `AuthMail`) и
   не переживает перезапуск — и не должно: срок челленджа задаёт бот.
5. Опрос — **без обязательного JavaScript**: кнопка «Проверить вход» работает
   всегда; автоопрос можно добавить как улучшение, но экран обязан работать без него.

**Тесты** (против подставного HTTP, реальные роуты):

- начало входа отдаёт ссылку, а `secret` не попадает в разметку;
- успешный опрос выдаёт **сессию кабинета** и уводит на подписки, а `GET
  /subscriptions` после этого показывает подписки аккаунта, отданного ботом
  (это и есть проверка «человек видит своё»);
- `denied` — экран отказа, сессии нет;
- `pending` — экран ожидания, сессии нет;
- опрос без начатого челленджа — отказ, а не 500.

**Шаги:** RED (тесты против подставного бота) → реализация → GREEN →
`ruff check .` и `ruff format --check .` → коммит
`Вход через Telegram: кабинет начинает и завершает флоу бота (#50)`.

**Готово, когда:** вход через Telegram выдаёт сессию кабинета по `account_id` от
бота, после входа на экране подписок видны подписки **этого** аккаунта, а стенд
`.claude/dev/cabinet_dev.py` по-прежнему поднимается.

## Review Focus

- **Никакого `chat_id` из формы** и никакой подстановки подтверждения: `account_id`
  приходит только из ответа бота, который проверил человека в Telegram (§3.3).
- **`secret` не течёт**: ни в разметку, ни в лог, ни в текст ошибки.
- **Разные отказы — разные экраны**: «отклонено человеком» и «сбой бота» требуют
  разных действий, и смешивать их нельзя.
- **Публичный и внутренний адреса бота не путать**: вход — публичный API, данные —
  `/internal/*`; второй наружу не выставляется.
