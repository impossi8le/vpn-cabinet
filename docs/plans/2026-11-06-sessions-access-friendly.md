# План: сессии, правила доступа, дружелюбность

> **Для агентов:** обязательный подключённый навык —
> `superpowers:subagent-driven-development`. Шаги отмечены `- [ ]`.

**Цель:** три работы, которые владелец попросил сделать подряд: вход перестаёт
теряться при перезапуске службы; бесплатный доступ делится на короткий (3 часа по
почте) и полный (30 дней за привязку Telegram); экраны становятся понятнее.

**Порядок:** сессии → правила доступа (сначала бот, потом кабинет) →
дружелюбность. Причина: сессии — боль сегодняшнего дня (каждый наш рестарт
выкидывает людей); правила доступа упираются в схему бота, где конфиги живут на
`chat_id`; дружелюбность — правки экранов, независимые от первых двух.

**Разбор:** [правила и дружелюбность](../2026-11-06-trial-rules-and-friendly-ui.md),
[путь человека](../2026-11-06-cabinet-ux-model.md),
[контракт §4](../2026-10-17-backend-contract.md).

## Общие ограничения

- Кабинет **не ходит в базу** — только внутренний HTTP к боту.
- **Зелёный — только подтверждённая защита**; ограничения и подсказки нейтральны.
- Тексты — русский, спокойный тон; **обещание в тексте обязано совпадать с кодом**.
- Никаких новых зависимостей; экраны работают без JavaScript.
- Тесты пишутся раньше кода и краснеют без правки.
- Репозиторий публичный: без адресов, хостов, ключей.

## Review Focus

- **Перезапуск службы** — вход обязан переживать его: это и есть смысл работы.
- **Бот недоступен** — вход не должен превращаться в 500; своё состояние и текст.
- **Сессия истекла или отозвана** — «выйти» обязано работать и на живой сессии.
- **Учёт короткого доступа по двум осям** — иначе бесплатная почта станет
  способом брать три часа бесконечно.
- **Экран окончания короткого доступа** — у человека три пути: привязать,
  оплатить, уйти; ни одного тёмного паттерна.

### Task 1: Сессии кабинета живут у бота

**Зачем.** Сейчас сессии — в памяти процесса (`cabinet/app.py:640`,
`SingleSessionStore`), поэтому `systemctl restart cabinet-app` разлогинивает всех.
У бота есть таблица `client_sessions` и роуты `/internal/sessions/*` — кабинет к
ним не подключён.

**Файлы:**
- Изменить: `cabinet/bot_client.py` (адаптер сессий рядом с `BotStore`),
  `cabinet/app.py` (сборка `SessionService` из адаптера), `cabinet/__main__.py`
  (боевые зависимости)
- Тест: `tests/test_sessions_live_store.py`

**Интерфейсы:**
- Форма сессии — как в `cabinet.sessions.SessionStore`: `create`, `find`,
  `touch`, `revoke`. Адаптер повторяет её поверх HTTP, как `BotStore` повторяет
  форму аккаунтов поверх корутин `BotClient`.
- Бот отдаёт: `POST /internal/sessions/for-account` → `{token, expires_at,
  account_id, created_at}`; `GET /internal/sessions/current` → `{account_id,
  chat_id, mail, expires_at}`; `POST /internal/sessions/revoke` — идемпотентный.

### Task 2: Короткий доступ по почте (сторона бота)

**Зачем.** Правило владельца: 3 часа по почте, 30 дней — за привязку Telegram.
Сегодня конфиг аккаунту без `chat_id` выдать некуда, поэтому начинаем со схемы.

**Файлы:** бот (`utils/db.py`, `services/cabinet_api_svc.py`), тесты бота.

**Требования:** выдача короткого доступа на `account_id` со сроком 3 часа; учёт
выдачи по двум осям (`account_id` и почта); чистка истёкших; отказ
`short_trial_used` при повторе; требование записывается разделом в ТЗ кабинета.

### Task 3: Экраны короткого и полного доступа (кабинет)

Экран «попробовать 3 часа», экран окончания с тремя путями, счётчик остатка в
подписках. Требования — §3 разбора.

### Task 4: Дружелюбность экранов

Правки §5 разбора: главное крупно, подписи короче, активный ключ на смене
региона, «сколько ждать» на экране кода.
